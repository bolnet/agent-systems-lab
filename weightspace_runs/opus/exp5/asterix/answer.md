## Design

**Strategy:** the player never moves horizontally, so it stays in column 5 and the game becomes a choice of row (1–8). Each row holds at most one entity, so one thresholded unit can read an entity's position and trail together. τ is the number of moves before an enemy reaches column 5.

**First layer (saturated, about ±1):**
- **Units 0–7, `P_r`:** the player is in row r.
- **Units 8–15, `I_r`:** an enemy is imminent in row r (at column 5, or one cell away and approaching, so τ≤1).
- **Units 16–23, `D_r`:** an enemy is near in row r (τ≤2).
- **Units 24–31, `G_r`:** treasure in row r is approaching or at column 5. Trail weights cancel treasure that has already passed.

**Second layer (AND-style rules for each player row p):**
- **Units 1–7 and 8–14, flee up or down:** these fire if the current row is `D`.
  - They never enter a row that is `I`.
  - They prefer a target row that isn't `D`.
  - As a tie-break, they prefer a direction where the row beyond the target is clear, because a sticky repeat could carry the player there.
- **Units 17–23 and 24–30, seek up or down:** these move toward the nearest treasure, using weights that halve with row distance and a slight bias upward on ties.
  - They only fire if the target row and the row beyond it are both not `D`.
  - They hold position if treasure is coming along the current row.
- **Units 0, 16, 15 and 31, centring:** these pull the player out of rows 1, 2, 7 and 8 when no treasure is there or further out, because edge rows have fewer escapes.

**Outputs:**
- Up and down start at −12 relative to no-op.
- An active seek or centring unit adds 20, and an active flee unit adds 30.
- Left, right and fire are fixed at −30, so the policy is close to deterministic.

I checked the weights by hand on sample cases, but nothing has been run.
